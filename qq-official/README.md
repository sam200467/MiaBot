# 美亚 · QQ 官方机器人接口

把 `mia-chat/` 的角色接到 **QQ 开放平台官方接口**（不是 NapCat 个人号）。

```
qq-official/
├── official-transport.cjs   传输层：鉴权、网关、心跳、收发、限流（协议全在这里）
├── mia-entry.cjs            入口：分流「指令」和「聊天」两条路，各自交给下面两层
├── mia-commands.cjs         指令层：解析、分发、出图队列、绑定会话
├── mia-voice.cjs            文案：美亚腔的所有字符串（只有字面量，没有逻辑）
├── mock-official.cjs        假的开放平台（token + REST + 网关），测试用
├── probe-official.cjs       连接探针：验凭据、拿 group_openid / user_openid
├── test-*.cjs               测试，全走 mock，不碰真接口
├── config.example.json      可提交的模板
└── config.local.json        **含 AppSecret，已 gitignore**
```

和 `qq/`（NapCat 版）是**并列的两个前端**，共用 `rio-chat/chat.cjs` 引擎和 `takase-core.cjs` 的
能力层，互不影响。指令文案、队列、绑定会话各写一份 —— 原因见 `mia-commands.cjs` 顶部的注释。

> 下文的梨绪（`qq/`）是另一条产品线，**不随本仓库分发** —— 提到它只是为了说明两边的边界；
> 涉及它的命令和路径在本仓库里跑不了，跳过即可。

## 两条入口

| | 怎么触发 | 经过模型吗 |
|---|---|---|
| **指令** | `/help`、`/b110`、`/定数表 14.2`… | **不经过**。程序直接解析执行 |
| **聊天** | @ 它说人话（「帮我查一下 id870」） | 经过。但模型只负责**挑工具和参数**，执行权在程序侧 |

聊天路径的六道校验（能力名 / 参数 / 权限 / @ 名单 / 绑定状态 / 冷却队列）全在 `mia-commands.cjs`。
**工具返回的数字、曲名、定数一律原样嵌进预写模板**，模型碰不到结果 —— 这跟人设里
「不编数字」是同一条防线。

群里**光有 `/` 前缀不执行指令**：全量群消息模式下别的 bot 打的 `/help` 也会送到这儿来。
判据按事件分 —— `GROUP_AT_MESSAGE_CREATE` 本身就意味着 @ 过；全量消息要真 @ 到美亚
（需要配 `botOpenid`，没配就只认前者）。逃生阀 `acceptBareGroupCommands` 默认关。

## 三条平台硬约束（决定了它和梨绪不一样）

1. **主动消息不可用**（`40034105`）。所以**不存在「群里发指令、机器人私聊你」**。
   绑定改为原地走群聊流程；QQ 官方机器人撤回接口当前不可靠，邮箱和密码由用户按提示
   立刻手动撤回。所有提示一律**回在原地**。
2. **被动回复窗口**：群 5 分钟 5 条、单聊 60 分钟 4～5 条，超了 `40034128`。
   出图上限超过窗口的项见 `mia-voice.cjs` 里 `jobQueued` 那句引导（队列拥堵时让用户走私聊）。
3. **没有 `get_msg`**。引用只用于「以回复形式展示」，读不到内容。

---

## 为什么不是 NapCat 那条路

| | NapCat 个人号 | 官方开放平台 |
|---|---|---|
| 合规 | 违反腾讯 ToS，可能封号 | 官方支持的正式能力 |
| 身份 | 数字 QQ 号 | openid（换 AppID 就变） |
| 群消息 | 全部能收 | 默认只收 @ 它的；全量要**群主**开 |
| 主动推送 | 可以 | 基本不可用（2025-04 起收敛） |
| 加群 | 随便加 | 未认证只能加自己当群主的群；个人认证后上限 500 |

美亚选官方这条，代价是**拿不到群里的上下文**（除非群主开全量）、**没有主动推送**。

## 首次配置

**顺序不能乱。缺任何一步的表现都是同一个：连得上，但一个事件都收不到。**

### 1. 配「服务范围」

开放平台 → 左侧 **服务范围** → 群聊「允许机器人被添加到任意群聊使用」**打开**。

不配的话平台不推群事件。

### 2. 加「开发体验用户」

开放平台 → **开发设置** → 拉到最下面 → 「开发体验号码设置」→ 添加你自己的 QQ 号。

> **开发中的机器人，只有这个名单里的账号能跟它对话。** 新版开放平台把旧版的「沙箱配置」改名叫这个了 —— 找「沙箱配置」是找不到的。

### 3. 填凭据

复制 `config.example.json` 成 `config.local.json`，填 `appId` / `clientSecret`（开发设置页）。

> `AppSecret` 等同机器人密码。这个文件已被根目录 `.gitignore` 的 `config.local.json` 规则忽略 —— **不要**改成别的名字，改名就不受保护了。

**指令层要的键也在这个文件里**，每个都有 `_说明` 写在旁边，照着填就行。三个会拦住启动的：

- `corePath` / `vaultHelperPath` —— 出图核心和凭据库。**文件不存在就拒绝启动**，
  这是有意的：否则每条指令会在运行期各失败一次，症状分散到没法查。
  这两个文件被 `.gitignore` 忽略（超过 GitHub 单文件上限），得自己准备。
- `vaultPath` —— 美亚**自己的**绑定库（按 openid 存，和梨绪那份不通用）。

### 3b. 共用别名库的前置条件（⚠ 别跳过）

`aliasDir` + `aliasScope` 要和梨绪一致才能共用 —— **两个都得一样**，
只改一个会得到两个并排的文件，看着像配好了其实各写各的。默认值已经配好了这一点。

但还有一条更要紧的：**两个 bot 必须都是带锁的版本。**

`song-alias-store.cjs` 的事务 + 文件锁是这轮才加的。梨绪跑的是打包好的
`qq/dist/takase-qq-bundle.cjs` / `qq/takase-qq-core.exe`，里面**还是加锁之前的实现** ——
一个加锁、一个不加锁，等于没加：不加锁那边仍然会拿启动时的内存副本覆盖整个文件，
把美亚刚加的别名抹掉。

所以在共用生效之前，**必须重跑一次 `node qq/build-qq-bot.js` 让梨绪也吃到这个修复**。
（那个脚本会重建 exe，属于发布动作，自己判断时机。）

⚠ 而重跑它需要仓库根目录有 `ongeki-core.exe` —— `build-qq-bot.js` 会把它作为资源嵌进
GUI exe，但没做存在性检查，缺了会在 csc 那一步以看不懂的方式失败。
根目录现在**没有**这个文件（它被 `.gitignore` 忽略）。`qq/qq-config.json` 里的
`corePath` 也指着同一个不存在的路径。

在梨绪重建之前，**把 `aliasDir` 指回美亚自己的目录**（`./data`）更安全 ——
各存各的只是别名分叉，不会丢数据。

### 4. 拿 group_openid

`allowedGroupIds` **不是群号**，是 `group_openid`（形如 `1A2B3C4D…`）。换 AppID、换环境都会变，必须现取。

```bash
node qq-official/probe-official.cjs          # 默认观察 60 秒
```

把机器人**走资料卡**加进群（手机 QQ → 联系人 → 机器人 → 找到它 → 添加到群聊），然后在群里 **真 @ 它一次**（从列表里选中，不是手打文字）。探针会把 `group_openid` 和 `user_openid` 打出来。

### 5. 填白名单并启动

```bash
node qq-official/mia-entry.cjs
```

**白名单为空时拒绝启动** —— 这是有意的，免得机器人误入陌生群。

## 全量群消息（可选，为了群聊上下文）

默认只有 `GROUP_AT_MESSAGE_CREATE`（群里 @ 它）。**普通群消息收不到**，所以美亚接不上「上面那首」「他刚才说的」这类指代。

想让它读得到群聊上下文，**只能群主操作，且每个群单独设**：

> 手机 QQ → 打开群 → 点机器人头像 → 右上角设置 → 「机器人可获取的群聊消息范围」 → 选「获取群内全部消息」

开了之后平台会推 `GROUP_MESSAGE_CREATE`。入口对这类事件**只记上下文、不回复**（否则群里每句话它都要搭腔）。

⚠️ 全量模式**没有撤回通知**，普通撤回消息仍可能留在上下文里。绑定状态机是例外：
邮箱和密码在进入上下文缓冲之前就被截走，绝不会送进模型。缓冲区是 12 条 / 10 分钟。

## 沙箱与正式

`config.local.json` 里的 `sandbox`：

- `true` → `sandbox.api.sgroup.qq.com`
- `false` → `api.bot.qq.com`（2026-08-10 起官方统一域名）

**⚠️ 这两个环境的事件互不相通。** 你的群/好友关系建在哪个环境，就必须连哪个环境 —— 错配的表现和「什么都没配」一模一样：**连得上、READY 拿得到、然后一个事件都不来**。

光看连接状态区分不出来（两个环境都能正常换 token、连网关）。**判据只有一个：有没有事件。**

切环境要重新取 `group_openid`。

## QQ 群 vs QQ 频道

两套互不相通的接口，传输层都支持：

| | QQ 群 | QQ 频道 |
|---|---|---|
| 事件 | `GROUP_AT_MESSAGE_CREATE` | `AT_MESSAGE_CREATE` |
| intent | `1<<25` | `1<<30` |
| 发送 | `/v2/groups/{id}/messages` | `/channels/{id}/messages` |
| 白名单字段 | `allowedGroupIds` | `allowedChannelIds`（未实装到入口） |

订了 `1<<30` 不会影响群消息，但**只订群聊的位时频道里一个事件都收不到**。

## 排查

**连不上**：跑探针，它会把原因打出来（凭据错 / 机器人没过审 / 不是沙箱成员）。

**连上了但收不到消息**：
1. 机器人没被拉进群，或沙箱成员没配
2. 群里没 @ 它 —— 默认只有 @ 才推
3. 沙箱配的群和实际用的不是同一批

**发不出去**：看日志。`40034128` = 被动回复超时或超次数（群聊 5 分钟 5 次、单聊 60 分钟 4～5 次）；`40034105` = 无权限（主动消息）；`40034100` = 频控。

## 日常运行

**双击 `启动美亚.vbs`** —— 无窗口后台跑，日志写到同目录 `mia.log`。
**双击 `停止美亚.vbs`** —— 只结束命令行里带 `mia-entry` 的 node 进程。

⚠️ **不要同时开两个** —— 两条 WebSocket 连接会让它把每句话回两遍。

> 这两个 VBS 是**生成物**，不提交。丢了就跑 `node qq-official/make-launchers.cjs` 重新生成。
> （VBScript 只认 UTF-16LE，手写容易踩编码坑，所以由脚本生成。）

## 一个必须知道的事

**官方平台只提供管道，不提供算力。**

```
群里 @ 美亚 → 腾讯网关推事件 → 你机器上的 mia-entry.cjs → 调 DeepSeek → 调 REST 发回去
```

所谓「部署到官方 bot」只是**在平台注册了一个身份**，逻辑一行都不在腾讯的服务器上跑。
**进程不跑，机器人就是死的** —— 群里 @ 它不会有任何反应。

开放平台里那个「**在线**」绿点，判定依据就是「有没有人连着网关」，不是「机器人已上线」。

和 NapCat 那套相比，省掉的是**账号**的负担（不用挂 QQ 客户端、不用扫码登录、不用家宽、不怕封号），
**不是省掉进程**。好处是它可以放到服务器上长期跑。

## 开发

```bash
node test-takase-core.cjs                                    # 共享核心
node test-song-alias-store.cjs                               # 别名库（含并发/事务/残留锁）
node --test --test-timeout=45000 qq-official/test-official-transport.cjs   # 传输层
node --test --test-timeout=45000 qq-official/test-mia-entry.cjs            # 入口（含指令/聊天两条路）
node --test --test-timeout=45000 qq-official/test-mia-commands.cjs         # 指令层（不起网关）
node --test --test-timeout=60000 qq/test-qq-entry.cjs                      # 梨绪不能退化
node --test --test-timeout=45000 rio-chat/chat.test.cjs                    # 引擎
```

**全部走 mock，不需要真实凭据、不花 API 费用。**

`--test-timeout` 留着当保险。它原先挡的是一个真问题：某条用例启动了 mock 却没关它，
一个 HTTP server 一直 listen 着，事件循环永远不空 —— 整个文件跑完之后进程不退，
等满 test-timeout 才被取消，**退出码非零**，于是这个套件没法当构建闸门用。
那条 `mock.stop()` 已经补上（传输层套件从 45 秒 + 失败变成 2 秒 + 通过）。
新写用例时请照着别漏：**起了 mock 就必须关**。

⚠ 测试里**不要在同一进程同时启动两个入口**：`configureAliases` / `configureCapabilities` /
`configureFormatting` / `setStatusProvider` 都是 `takase-core` 的模块级单例，后注册的会盖掉前一个。
生产上是两个独立进程，所以没问题。

排查连接问题：`node qq-official/probe-official.cjs`，它带**帧级探针**，会把网关上收到的每一帧都打出来 ——
连上了但收不到事件时，靠它区分「连接坏了」和「平台没推」。

**它同时是上线前的闸门。三件事已经实测过了（2026-09-19，正式环境）：**

| 问题 | 实测结论 |
|---|---|
| 会不会对同一条消息双投递？ | **不会。** 但平台的**事件名会随群设置切换**：<br>没开全量消息 → @ 走 `GROUP_AT_MESSAGE_CREATE`，**正文里连 `mentions` 字段都没有**；<br>开了之后 → @ 改走 `GROUP_MESSAGE_CREATE`，带 `mentions`，AT 事件**不再推**。<br>⚠ 所以「两种事件名都出现过」不等于双投递，要按指纹配对看。<br>→ `d.id` 作幂等键是安全的，幂等闸留着当保险。 |
| 怎么判「确实 @ 到美亚」？ | **用 `mentions[].is_you`** —— 平台直接告诉你「这个 @ 的就是你自己」。<br>⚠ 两个坑：① `mentions` 里的 id 与 READY 给的 `botId` **不是一套 id 空间**（openid vs 数字号），拿它们比对永远不命中；<br>② 全量模式下**别的 bot 被 @ 的消息也会推过来**（实测收到过另一只 bot 的 `/login`），判据用「mentions 非空」就会去抢答别人的指令。<br>→ `botOpenid` 已废弃，别填。 |
| 别人的消息能当被动凭据吗？ | **能。** 用新消息的 `msg_id` + 引用指向旧请求，平台接受。<br>→ `reuseLatestPassiveCredential` 已实现并默认开启。<br>⚠ 不是万能补丁：那之后没人在群里说话，仍然没有新鲜凭据可用。 |

**一个必须知道的连带后果**：开了全量群消息之后**平台不再推 AT 事件**。所以
「按事件名判 @」的写法会让美亚在那种群里**完全不吭声**（指令不执行、聊天也不回）。
代码现在两种模式都走 `mentionsSelf`，不要改回按事件名判。

**⚠ 全量群消息还会把 `@` 带进正文**：AT 事件的正文平台已经替我们摘掉了（`" 2"`），
全量事件的正文里 @ 是 `<@openid>` 标记（`"<@5FE5240E…> /help"`）。传输层在
`normalize` 里统一摘掉，否则 `parseCommand` 按「开头是不是 `/`」判会认不出指令。
**摘掉的 @ 会进 `mentions`，而那里装的是美亚自己** —— 所以 `mentionedOpenids`
必须**排除自己**，否则「@美亚 /牌子 耀击」会被当成「查美亚自己」，回一句
「TA 还没把账号交给美亚过」（线上实测踩到过，绑了账号也查不了牌子）。

## 指令面板（输入框打「/」拉出清单）

`mia-command-panel.cjs` 用官方的**指令面板**接口注册一个群聊面板，用户在输入框打 `/`
就能看到美亚会什么。

**它只做发现入口，一行执行逻辑都没有**：面板元素是 `type=command`，官方文档写明
「点击后该内容会填入聊天输入框」—— 也就是说点一下得到的就是 `/帮助` 这几个字，
跟手打一模一样，之后照常走 `mia-commands.cjs` 的硬路由、@ 判断、权限、冷却、队列。
面板坏了最多是难看，不会让谁绕过校验。

```bash
node qq-official/mia-command-panel.cjs --dry-run              # 只打印要发的 payload
node qq-official/mia-command-panel.cjs --register             # 注册/更新（默认只挂 allowedGroupIds）
node qq-official/mia-command-panel.cjs --list                 # 看现有面板
node qq-official/mia-command-panel.cjs --detail <panel_id>    # 看它挂在哪些群（列表接口不返回群列表）
node qq-official/mia-command-panel.cjs --delete <panel_id>
```

**默认只挂 `target_type=specific` + `config.local.json` 的 `allowedGroupIds`**，
不会一上来推给所有群；要全局得显式加 `--all-groups`。

> 它只连 REST（不建网关连接），所以 **bot 正跑着的时候也能安全执行**，不会有两条 WS 连接。

### 面板文案的坑：错误码会骗人

`/绑定` 的描述原本写成「把你的大饼账号交给美亚（要私聊）」，平台**拒绝**它 ——
报的却是 **`40030013`「超出数量限制」**。排查了半天才发现超的**不是数量是文案**：
同一个意思换成别的说法就过（半角括号过、去掉括号过、重写也过），而那句原话每次都被拒、
稳定复现。而且它提示「具体限制值见返回信息中的 limit」，响应体里**根本没有 limit 字段**。

⚠ 所以面板文案要当成**面向陌生人的公开文案**来写，别出现「把你的账号交给…」这类句式；
被 `40030013` 拦下来时，先怀疑文案，别去数元素个数。排查时用 `--dry-run` 把 payload 打出来，
再一条一条单独试（注意 `POST /v2/panels` 只有 **10 QPM**，连着打会变成 `40023001` 限流，
那就更难分辨了）。

### 几个实测细节

- `POST /v2/panels` 10 QPM，一个机器人**最多 20 个面板**（跨 scope 共享），一个面板**最多 20 个元素**。
  我们正好 20 条命令 —— 再加命令会撞上限，测试会拦下来，用 `exclude` 挑掉几条。
- 平台存的时候**会去掉 `name` 开头的斜杠**（发 `/帮助`、读回来是 `帮助`），返回的键序也不同。
  所以判「内容有没有变」必须**归一化之后**再比，直接 `JSON.stringify` 会永远判成有变化、
  每次白发一个 PUT。
- `REMARK` 是认领面板用的（列表接口没别的东西能区分来源）。**不要手改** ——
  改了脚本就找不到它，会去建第二个，白烧名额。
- 这个 CLI 只在开发目录里，**不进部署包**：面板是挂在 AppID 上的，跟哪台机器跑 bot 无关。

## 别名的规则（美亚这边刻意做得简单）

**加别名：谁都能加，加了就上了。删除别名：只有白名单里的人能删，删了就没了。**

就这么两条。**没有「候选 / 复核」那一道**（2026-09-19 定）：

- 命令表里没有 `/别名候选`、`/驳回别名候选`
- `mia-entry.cjs` 的适配器**刻意不接 `alias.propose`** —— 那是「引擎自己猜出来的叫法
  先记成候选、人工确认后才进正式库」的流程。不接它，`chat.cjs` 的 `recordCandidate`
  在第一行就返回，**不会再往候选库写任何东西**
- `alias.resolve` / `alias.titles` 留着：它们负责在闲聊里认出「电管」这类叫法，不可少

删除白名单是 `config.local.json` 的 `aliasDeleteOpenids`（openid 数组，空 = 谁都不能删）。
⚠ openid 换 AppID 或换环境就会变，换环境后要重新探。

> 梨绪（`qq/`）那边**没有跟着改** —— 它有自己的一份命令表，候选流程仍在。
> 要一起简化说一声，改的是另一份文件。

## ⚠ 界面版美亚的数据放在哪（踩过一次，别再踩）

界面的 `EnsureMia()`（`takase-qq-gui.cs`）在**换包时会 `Directory.Delete(runtime/mia, true)`
整个删掉重解**：

```csharp
if(File.Exists(mark) && File.ReadAllText(mark).Trim()==hash) return;  // 包没变就不动
if(Directory.Exists(mia)) Directory.Delete(mia,true);                 // 包变了 → 全删
```

所以**凡是会被写入的数据都不能放在 `runtime/mia/` 里面**。

路径写过一次 `../data`，展开是 `runtime/mia/data` —— 正好在那一刀里。
症状是**每重新构建一次 exe，美亚的账号绑定就没了，得重绑**，
而人只会以为是自己的操作问题，查不到「重建」这个原因上。

现在它们统一放在 `root/data/mia`（`%LOCALAPPDATA%/TakaseQqBot/data/mia`）——
从 `runtime/mia/qq-official/` 往上三级就是 root，`root/data` 是梨绪的数据目录，
界面只创建、从不删除：

| 键 | 值 | 展开 |
|---|---|---|
| `workDir` | `../../../data/mia` | `root/data/mia` |
| `outputDir` | `../../../data/mia/output` | 同上 |
| `vaultPath` | `../../../data/mia/bindings.dat` | 同上（绑定在 `workDir` 下，目录会先被建出来） |
| `aliasDir` | `../../../data/mia`（或共用时 `../../../data`） | 同上 |

`make-mia-zip.cjs` 里有条自检专门守这个不变量：**这四个键必须以 `../../../data/` 开头**，
改回去会当场报错并说明原因。

> 和它相对的是两个 exe：它们**应该**放在 `runtime/`（`../../`），
> 因为 `EnsureRuntime()` 每次启动都按哈希比对、需要时会重新解压覆盖。

### 账号绑定存在哪个 id 下

绑定的键是事件里的 `author.member_openid`（群）/ `author.user_openid`（私聊）。
**实测（2026-09-19）：这两个对同一个人是同一个值** —— 在私聊里绑的号，在群里查得到。
所以「私聊绑定、群里查分」这条链路是通的。

> 还没验过的：跨群是否通用。`member_openid` 官方描述是「群成员 openid」，
> 字面意思是按群切分的；但实测私聊和群共用同一个值，说明至少不是严格按群。
> 只有一个群可测，等你进了第二个群再确认。

改 `rio-chat/chat.cjs` 或 `takase-core.cjs` 时两边都会受影响，所以上面那两组测试都要跑。
# 歌曲搜索

`/搜索歌曲 サド`：搜索本地音击曲库，不用绑定账号。支持部分曲名、别名、Bot ID（如 `id870`）、假名与全半角归一化，以及少量拼写错误的候选提示。

搜索只接收曲名线索，不支持等级或前缀条件语法。结果只显示曲名与各难度已知定数；未知定数明确标注。结果每页最多八首；用 `--page 2` 翻页。

也可以直接 @ 美亚说「有没有哪首歌开头是サド的」或「你能查到这首歌吗：サドマミホリック」。自然语言由独立的语义路由结合会话上下文选择工具，缺参数时追问；`/单曲` 仍查询个人成绩。

更新源码后需重启；如果运行的是打包部署版，需要重新打包并替换部署文件后重启。已有 QQ 指令面板需重新注册才会显示搜索项，手输命令无需更新面板。

闲聊路由与角色回复分离：功能请求通常只需一次路由模型调用；普通闲聊多一次简短路由调用。模型判断不能保证零误判，执行仍经过权限、参数、绑定与队列检查。路由失败不执行工具，提示重试或使用指令。
